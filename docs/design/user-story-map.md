# all2api 用户故事地图（v1.1）

> 本文是面板与 CLI 交互面的**唯一规格源**：任何屏幕、按钮、接口的新增/删除都必须先在本文落故事，再动代码。
> v1.1 主人裁定：**① 三平台（workbuddy / qoder / trae）分面板管理**——各自的账号、任务设置、模型独立成屏；**② 添加账号必须在面板内完成**（"文件即账号"裁定废止，文件只作凭证的落盘位置）。

## 1. 产品与用户

- **产品**：自托管的 OpenAI 兼容网关——把 WorkBuddy/CodeBuddy 与 Qoder 的账号额度，转成本机 `:7800/v1` 的 API 服务。
- **用户**：单一主人（self-hosted）。没有多租户、没有权限分级。主人身兼两顶帽子：
  - **使用者**（每天）：Cherry Studio / Claude Code / Codex CLI 调 API，不打开面板；
  - **运维者**（偶尔）：看账号还剩多少、为什么请求失败了、换过期凭证、改端口和 key。
- 因此面板的唯一使命：**让运维者在 10 秒内回答"网关现在健不健康、为什么不健康"**。不是功能大而全的控制台。

## 2. 信息架构（v1.2：账号池二级菜单 = 总览 + 分平台明细）

```
左栏：
  账号池（二级菜单，主人裁定）
    ├ 总览        ← 全平台摘要：聚合状态卡 + 各平台用量摘要卡（含下钻链接）
    ├ WorkBuddy   ← 该平台账号明细（表格 + 添加账号）
    ├ Qoder       ← 同上
    └ Trae        ← 同上（未接入时引导）
  任务           ← 该平台适用的任务与 cron（workbuddy 四任务；qoder/trae 按其任务面）
  模型           ← 该平台模型目录
全局页（不随平台切）：
  连接 ｜ 配置 ｜ 日志
```
（v1.2 主人裁定：平台选择器从顶栏移入左栏"账号池"二级菜单；总览页只放摘要与用量摘要，不放明细表格。）

- 平台切换记忆在内存（刷新回到 workbuddy，不落 storage 红线不变）。
- 未启用的平台在平台选择器中显示"未启用"，点进去只有"启用此平台"引导（写 config.sources.<id>.enabled）。
- 任务按平台拆分后的归属：workbuddy = signin/active_check/cat_travel/token_keepalive；qoder/trae = 当前无上游任务面，任务屏显示"该平台暂无定时任务"（不显示假卡片）。

## 3. 故事地图（横向 = 时间旅程，纵向 = 优先级）

| 旅程阶段 | P0（本版必须） | P1（下一版） | P2（以后） |
| --- | --- | --- | --- |
| ① 安装 | setup.exe 向导（选目录/模式/自启）；装完即有可跑的空网关 | 卸载时可选保留数据提示 | — |
| ② 接入账号 | **面板内"添加账号"向导（按平台分化，见 §4）**；空池引导指到向导 | 批量导入 | — |
| ③ 日常使用 | `/v1` 全链可用（客户端 Base URL: `http://localhost:7800/v1`）；裸模型名自动路由 | — | — |
| ④ 监控 | **分平台账号池屏**：每账号状态/积分/健康/到期；**分平台任务屏**：该平台任务 cron+最近运行；**日志屏**（全局）：环形缓冲+级别过滤+按平台过滤 | 用量统计（token/请求数） | 积分构成/到期分布（FEFO） |
| ⑤ 连接客户端 | **连接屏**：Base URL、当前 key、模型清单+复制 | 一键生成各客户端配置片段 | — |
| ⑥ 运维配置 | **配置屏**（全局）：fields 元数据驱动、保存落盘、restart_required 标注；改 key 后面板自动带新 key；**平台开关也在配置屏**（一键摘源） | 表单内联校验错误定位 | 配置历史/回滚 |
| ⑦ 故障处置 | 账号 recover（手动重置冷却/熔断）；日志里能看到失败原因 | 失败时面板横幅直达相关日志 | 邮件/webhook 告警 |

## 4. 添加账号故事（v1.1 核心，按平台分化）

| 平台 | 向导形态 | 依赖的后端 | 优先级 |
| --- | --- | --- | --- |
| **qoder** | **粘贴 PAT**：一个输入框（`pt-…`）→ 保存即生效（写 `auths/qoder-pat.txt` + 热注册）；换号=粘贴新的 | 新端点 `POST /api/accounts/qoder`（panel 批落地） | **P0** |
| **workbuddy** | **设备授权三步流**：① 面板取授权链接（后端调 `/v2/plugin/auth/state?platform=CLI`）→ ② 用户在浏览器打开并登录 → ③ 回调/复制回链接粘进面板 → 后端轮询换 token 并落盘 `auths/workbuddy-<uid>.json`。**备用路径：直接粘贴完整凭证 JSON**（从官方桌面端 `CodeBuddyExtension\Data\Public\auth\*.info` 复制，协议报告已实证其字段） | 新端点 `POST /api/accounts/workbuddy/login-url` + `…/complete`（panel 批落地） | **P0（凭证粘贴）+ P1（设备授权流）** |
| **trae** | 登录链接+回调粘贴（vhub 同款三步） | trae 平台本身未接入网关，向导先显示"平台未接入" | P2（随 trae 接入） |

- 添加成功即时刷新账号池屏；重复 uid 幂等覆盖并提示。
- 文件落盘仍走 auths\（磁盘上可备份/迁移，但**用户不再需要碰文件**——v1.0"文件即账号"的裁定按主人指示废止）。

## 5. 关键故事（验收用）

1. **"我刚装好，下一步干嘛？"** → 打开面板，账号池屏明确说"池是空的" + **「添加账号」按钮** → qoder 粘 PAT / workbuddy 粘凭证 JSON 或走授权流（P0）。
2. **"API 报 503 了，为什么？"** → 切到对应平台的账号池屏：所有账号冷却中/积分 0 → 日志屏过滤 error 直接看到上游拒绝原因 → 对该账号点 recover 或重新添加（P0）。
3. **"签到跑了吗？"** → workbuddy 平台的任务屏：signin 卡片显示最近运行时间与 success/failed 计数（P0）。
4. **"我想换个端口/key"** → 配置屏改 listen/api_key → 保存落盘 → 提示重启 → 重启后生效；改 key 后面板后续请求自动带新 key（P0）。
5. **"新客户端怎么接？"** → 连接屏给出 Base URL/key 状态/可用模型清单，一键复制（P0）。
6. **"我想给 Qoder 加个号"** → 平台选择器切 Qoder → 账号池 → 添加账号 → 粘 PAT → 池里立刻出现新账号（P0）。
7. **"token 会过期吗？"** → 不用管：到期/401 自动刷新并回写凭证文件（后端自治，面板只展示 expires_at）。凭证彻底失效 → 账号标记 disabled，账号池屏明示"重新添加"（P0）。

## 6. 明确不做（本产品定位裁剪）

- 多用户/权限系统（self-hosted 单主人）；
- 账号额度/用量的小时级图表（上游无历史接口，做出来是假数据）；
- 批量手动触发签到/旅行按钮（调度器已自动跑；手动批量触发属 P1"扫描待办"故事，需后端任务队列支撑）；
- trae 平台的账号添加向导（平台未接入，先显示引导而非假表单）。
