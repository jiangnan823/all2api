# all2api 用户故事地图（v1.0）

> 本文是面板与 CLI 交互面的**唯一规格源**：任何屏幕、按钮、接口的新增/删除都必须先在本文落故事，再动代码。
> 参考：wb2api（逆向提取的信息架构）只作素材，不作规格——规格以"我们的用户要完成什么"为准。

## 1. 产品与用户

- **产品**：自托管的 OpenAI 兼容网关——把 WorkBuddy/CodeBuddy 与 Qoder 的账号额度，转成本机 `:7800/v1` 的 API 服务。
- **用户**：单一主人（self-hosted）。没有多租户、没有权限分级。主人身兼两顶帽子：
  - **使用者**（每天）：Cherry Studio / Claude Code / Codex CLI 调 API，不打开面板；
  - **运维者**（偶尔）：看账号还剩多少、为什么请求失败了、换过期凭证、改端口和 key。
- 因此面板的唯一使命：**让运维者在 10 秒内回答"网关现在健不健康、为什么不健康"**。不是功能大而全的控制台。

## 2. 故事地图（横向 = 时间旅程，纵向 = 优先级）

| 旅程阶段 | P0（本版必须） | P1（下一版） | P2（以后） |
| --- | --- | --- | --- |
| ① 安装 | setup.exe 向导（选目录/模式/自启）；装完即有可跑的空网关 | 卸载时可选保留数据提示 | — |
| ② 接入账号 | 空池引导："把 workbuddy-*.json 放入 auths\ 后重启"；账号自动发现+积分播种 | 面板内粘贴凭证（热生效） | 浏览器登录向导（wb2api 式） |

## 3. 关键故事（验收用）

1. **"我刚装好，下一步干嘛？"** → 打开面板，账号池屏明确说"池是空的，去 auths\ 放凭证文件"（P0）。当前缺口：旧 connect 空壳页给不了这个指引。
2. **"API 报 503 了，为什么？"** → 账号池屏一眼看到：所有账号冷却中/积分 0 → 日志屏过滤 error 直接看到上游拒绝原因 → 对该账号点 recover 或换凭证（P0）。
3. **"签到跑了吗？"** → 任务屏：signin 卡片显示最近运行时间与 success/failed 计数（P0，M5 已交付数据）。
4. **"我想换个端口/key"** → 配置屏改 listen/api_key → 保存落盘 → 提示重启 → 重启后生效；改 key 后面板后续请求自动带新 key（P0，本版实现）。
5. **"新客户端怎么接？"** → 连接屏给出 Base URL/key 状态/可用模型清单，一键复制（P0；M5b 删掉了旧空壳页，按本故事重建为真屏）。
6. **"token 会过期吗？"** → 不用管：到期/401 自动刷新并回写 auth 文件（后端自治，面板只展示 expires_at）。凭证彻底失效（refresh 也 401）→ 账号标记 disabled，账号池屏明示"需重新获取凭证"（P0）。

## 4. 明确不做（本产品定位裁剪）

- 多用户/权限系统（self-hosted 单主人）；
- 面板内增删账号的表单（**文件即账号**：auths\ 目录就是账号管理界面，重复建设无收益）；
- 账号额度/用量的小时级图表（上游无历史接口，做出来是假数据）；
- 批量手动触发签到/旅行按钮（调度器已自动跑；手动批量触发属 P1"扫描待办"故事，需后端任务队列支撑，本版不做假按钮）。
