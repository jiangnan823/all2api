# all2api 与 wb2api（参考实现）面板差距对照（v1.1 附册）

> 依据主人提供的两张 wb2api 实图（账号池表格 + 成长任务队列弹层）与我对参考实现的静态分析。
> 处置列 = 采纳 / 裁剪 / 后批，均落回 user-story-map 与 interaction-matrix。

## 1. 账号池表格（对照截图 1）

| wb2api 的列/元素 | 我们现状 | 处置 |
| --- | --- | --- |
| **账号显示"昵称"+uid 短码**（"40 多岁的年轻小伙 3a9f5928…"） | 只有 uid 短码 | **采纳 P0**：凭证 JSON 里本来就有 `account.nickname`，账号表格主显昵称、副显 uid；加载时随凭证读入 |
| **积分"5439 / 6674"双值+进度条** | 只有单值 | **采纳 P0**：workbuddy 余额接口可取 CycleCapacityRemain 与总额（配额），表格显 `剩余/总额`+条 |
| **成功 / 失败 计数**（2568 / 0） | 无 | **采纳 P0**：路由的 SendChat 结果回灌处按账号累计（pool.Account 加 success/fail 计数，重启清零如实标注"本次运行"） |
| **在途**（并发中请求数） | 无 | **采纳 P0**：dispatch 发送前后计数（host 侧 per-account in-flight 原子计数） |
| **用量徽章组**（2679 次 / 452.4M tok / 739ms / 47.8tok/s） | 无 | **裁剪→P1**：本版先做"次数"徽章（计数已有），token/速度徽章需 usage 统计面（P1 故事 ④），本版不造假数 |
| **最近成功**（"29 秒前"） | 无 | **采纳 P0**：UpdateHealth success 时记 last_success 时间戳 |
| **429 rate limit 副标**（状态徽标下的限流说明） | 无 | **采纳 P0**：冷却原因随徽标显示（429/额度/手动） |
| **行内按钮：已签｜余额｜任务｜暂停选号｜禁用｜移除** | 只有恢复/删除 | 部分采纳：**恢复（=恢复）、暂停选号（P0：per-account 选号开关，池 Select 跳过）、移除（=删除，已有）**；**"已签/余额/任务"三键裁剪**——它们是 wb2api 的单账号详情弹层入口，我们 P0 用任务屏+行内数据承载，账号详情弹层属 P1 |
| 顶部批量按钮（全部签到/旅行巡检/活跃上报/全部保活） | 无 | **裁剪**：调度器已自动跑；手动批量触发等待办队列故事（矩阵 §2 不变） |

## 3. 平台维度（主人裁定 + 参考实现事实核对）

| 项 | 事实 | 处置 |
| --- | --- | --- |
| **trae 签到** | **vhub 有完整实现**：`/trae/api/v2/ug/checkin_credits/status|claim`、9 点定时+启动补跑（幂等）、16 位数字设备 ID（每号互异、首字符非 0）、`req_source:2` claim、活动未开放(enable=false)分支 | **采纳 P0**：trae 接入网关时签到为第一批能力（含"未开放"分支）；调度任务表加 trae_checkin |
| **qoder 签到** | **两个参考实现均无签到端点**：qoder 额度走 OpenAPI Quota 体系（userQuota/addOnQuota/orgResourcePackage，订阅周期额度），无 checkin 接口 | **如实标注**：qoder 任务屏显示"该平台无签到任务（额度为订阅制）"；若主人在其他客户端见过 qoder 签到，提供该客户端的请求抓包后我再调研 |
| qoder 额度展示 | Quota 结构含 total/used/remaining/percentage + 到期 | **采纳 P0**：qoder 账号积分列展示 remaining（含 userQuota+addOn 可用部分），比单数字诚实 |
